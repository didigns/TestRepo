# OwnYourPC — Architecture & Design Blueprint

> **한 줄 요약**: 사용자 PC 안에서 100% 로컬로 도는, 문서 RAG Q&A + 실시간 회의 전사/회의록 생성을 제공하는 프라이버시-우선 데스크톱 제품. 클라우드 전송 0, SaaS급 UX.

버전: v0.1 (foundation) · 최종 수정: 2026-07-06

---

## 1. 제품 목표 (Product Goals)

| # | 목표 | 성공 기준 (측정 가능) |
|---|------|----------------------|
| G1 | 지정 폴더의 문서/PDF를 자동 벡터화 → 로컬 DB 저장 | 파일 추가 후 30초 내 검색 가능, 100% 오프라인 |
| G2 | 저사양 노트북에서 도는 SLM으로 RAG Q&A | 12GB RAM 노트북에서 첫 토큰 < 3s, 답변 근거(citation) 100% 표기 |
| G3 | 할루시네이션 억제 | 근거 없는 주장 시 "모름" 응답. 답변의 모든 사실 문장에 출처 span 연결 |
| G4 | 실시간 회의 전사 + 회의록 + 요약 + PDF | 전사 지연 < 2s(base 모델), 회의 종료 후 60초 내 PDF 생성 |
| G5 | 설치 시 하드웨어 감지 → 모델/파라미터 자동 선택 | 3개 이상 티어, 사용자 오버라이드 가능 |
| G6 | 품질/보안 리뷰 게이트 | 자동 점수 < 임계값이면 릴리스 차단 |

**비목표 (Non-goals, v0)**: 멀티유저 서버, 클라우드 동기화, 모바일 앱, 파인튜닝.

## 2. 기술 스택 결정 (Stack Decisions)

리서치(2026-07 기준) 결과에 근거한 확정 스택. 각 선택의 *이유*를 함께 기록한다.

### 2.1 로컬 LLM (SLM)
- **선택: Google Gemma 4 E4B via Ollama** (`ollama pull gemma4:e4b`).
  - 유효 4.5B 파라미터(임베딩 포함 8B), 128K 컨텍스트, **텍스트/이미지/오디오 멀티모달**, Apache 2.0.
  - 요구사항: 6GB VRAM 또는 12GB 통합 RAM. 저사양 노트북 타깃과 정확히 부합.
  - 오디오 네이티브 → 회의 요약 파이프라인에서 이점.
- **폴백: Gemma 4 E2B** (초저사양, 8GB RAM 이하).
- **런타임 추상화**: Ollama HTTP API를 기본으로 하되, `llm.py`에서 provider 인터페이스로 감싸 llama.cpp/직접 GGUF 로딩으로 교체 가능하게 설계.

### 2.2 임베딩 모델
- **기본: `nomic-embed-text`** (137M, 274MB, 8K 컨텍스트) — CPU에서 쾌적, RAG 품질/자원 균형의 스위트스팟.
- **초저사양 폴백: `all-MiniLM-L6-v2`** (23M, 46MB, 83ms 지연).
- **고품질 옵션: `Qwen3-Embedding-0.6B`** (MTEB 70.7, 32K 컨텍스트) — 여유 있는 하드웨어에서.
- 모두 CPU 구동 가능 (임베딩은 GPU 불필요).

### 2.3 벡터 DB
- **선택: LanceDB** — 디스크 기반 Lance 컬럼 포맷, 인프로세스(서버 불필요), RAM 초과 데이터셋 처리, IVF-PQ 인덱싱, 자동 버전관리(time-travel).
  - 데스크톱 로컬-퍼스트 + 대용량 문서 컬렉션에 최적. 노트북에서 10억 벡터도 100ms 내 검색 벤치 존재.
  - 메타데이터+텍스트+벡터를 단일 테이블에 저장 → citation용 원문 span 보관에 유리.
- **대안**: ChromaDB(API 단순, ~100만 벡터 이하 프로토타이핑). v0는 LanceDB로 통일.

### 2.4 STT (회의 전사)
- **선택: faster-whisper (CTranslate2)** — Python 파이프라인 친화, `tiny`/`base` 모델은 최신 CPU에서 실시간 이상.
  - Apple Silicon 타깃 시 `whisper.cpp`로 스왑 (3× 빠름). provider 인터페이스로 추상화.
- **화자 분리**: `pyannote.audio` (또는 WhisperX) — 세그먼트 confidence → 클러스터링. 옵션(무거움), 티어별 활성화.

### 2.5 애플리케이션 셸
- **백엔드: Python + FastAPI** (로컬 127.0.0.1 서비스). ML 생태계·개발 속도.
- **프론트/셸: Tauri (Rust + 웹뷰)** 권장 — Electron보다 가볍고(저사양 타깃), Python을 사이드카 프로세스로 번들. 배포는 PyInstaller로 백엔드 동결 + Tauri 인스톨러.
  - v0 코드베이스는 **백엔드 API 우선**으로 구현 → UI 셸은 이 API를 소비. UI는 후속 마일스톤.

### 2.6 문서 파싱
- PDF: `pymupdf`(fitz) — 빠르고 레이아웃 보존. 스캔본은 `ocrmypdf`/tesseract 폴백.
- Office: `python-docx`, `python-pptx`, `openpyxl`.
- 텍스트/마크다운/코드: 직접. HTML: `trafilatura`.

## 4. 데이터 흐름

### 4.1 인제스천 (문서 → 벡터)
1. `watchdog`가 지정 폴더 감시 → 생성/수정/삭제 이벤트.
2. 파일 해시(SHA-256) + mtime으로 변경 감지, 중복/미변경 스킵.
3. 타입별 파서로 텍스트 + 구조(페이지/헤딩) 추출.
4. 구조 인지 청킹(heading 경계 우선, 목표 토큰 ~512, 오버랩 ~64). 각 청크에 `source_path, page, char_start, char_end` 메타 부착 → **citation span의 근거**.
5. 임베딩 → LanceDB upsert. 삭제 파일은 tombstone.

### 4.2 RAG 질의 (할루시네이션 억제 핵심)
1. 질문 임베딩 → LanceDB top-k(기본 8) 벡터 검색 + 선택적 키워드 하이브리드(BM25).
2. 리랭킹(옵션, 티어 상): cross-encoder로 재정렬.
3. **컨텍스트 예산 관리**: 청크를 컨텍스트 창에 맞게 패킹, 각 청크에 `[S1]..[Sn]` 라벨.
4. **Grounding 프롬프트**: "제공된 출처만 사용. 각 사실 문장 끝에 [Sn] 인용. 출처에 없으면 '제공된 문서에서 찾을 수 없습니다'라고 답하라."
5. 생성 후 **후검증(post-check)**: 인용 라벨이 실제 검색된 출처에 존재하는지, 인용 없는 사실 문장이 있는지 검사 → 실패 시 재생성 또는 "불충분" 표시.
6. **신뢰도 게이팅**: top 유사도 < 임계값이면 답변 대신 "관련 문서를 찾지 못했습니다".

### 4.3 회의 파이프라인
1. 오디오 캡처(마이크/시스템 오디오) → 링버퍼, VAD로 발화 구간 분할.
2. 청크 단위 faster-whisper 전사 → 라이브 자막 스트림(WebSocket).
3. (옵션) 화자 분리 병합 → `[화자 A] ...`.
4. 회의 종료 → 전체 전사 정리 → SLM 상세 요약(주제/결정사항/액션아이템 구조화 JSON).
5. 회의록 PDF 렌더(제목/참석자/요약/액션아이템/전문) → 사용자 제공.

## 5. 모델 선택 로직 (설치 시)

`hardware.py`가 감지 → 티어 결정. 사용자는 UI에서 오버라이드 가능.

| 티어 | 조건 (RAM / GPU) | LLM | 임베딩 | STT | 리랭커/화자분리 |
|------|------------------|-----|--------|-----|----------------|
| **Low** | < 12GB RAM, GPU 없음 | gemma4:e2b | all-MiniLM-L6-v2 | whisper tiny | 끔 |
| **Mid** | 12–24GB RAM 또는 6GB+ VRAM | gemma4:e4b | nomic-embed-text | whisper base | 리랭커 옵션 |
| **High** | 24GB+ RAM / 8GB+ VRAM | gemma4:e4b (긴 컨텍스트) | Qwen3-Embedding-0.6B | whisper small/medium | 둘 다 켬 |

파라미터 노출: 컨텍스트 길이, top-k, temperature(기본 0.2, 사실성 우선), 청크 크기, 유사도 임계값.

## 6. 할루시네이션 억제 전략 (요약)

"완전 배제"는 불가능하나, 다층 방어로 실무 수준까지 억제한다:
1. **검색 기반 grounding** — 모델 내부 지식 대신 검색된 출처만 사용하도록 지시.
2. **인용 강제** — 모든 사실 문장에 `[Sn]` 필수, 후검증으로 미인용 문장 탐지.
3. **신뢰도 게이팅** — 검색 유사도 낮으면 답변 거부("모름").
4. **낮은 temperature (0.2)** — 창작 억제.
5. **추출형 폴백** — 생성 실패/저신뢰 시 원문 발췌 직접 제시.
6. **평가 하니스** — 골든 Q&A 셋으로 groundedness/citation 정확도 회귀 측정(§8).

## 7. 보안 설계

- **로컬-온리**: 외부 네트워크 호출 없음. 방화벽 규칙 문서화. 텔레메트리 옵트인·기본 끔.
- **API 인증**: FastAPI는 127.0.0.1 바인딩 + 세션 토큰(셸이 생성). CORS 잠금.
- **저장 데이터**: `~/.ownyourpc/` 권한 제한. 선택적 at-rest 암호화(사용자 비밀번호 → 키 파생).
- **입력 안전**: 파싱 시 경로 탈출·심볼릭링크·과대 파일 방어. PDF 폭탄/외부 엔티티 차단.
- **의존성**: SBOM 생성, `pip-audit`로 취약점 스캔.
- **PII**: 데이터는 사용자 소유. 모델이 로컬이므로 프롬프트 유출 없음.

## 8. 품질/보안 리뷰 게이트 (릴리스 루프)

빌드마다 자동 채점 → 임계값 미달 시 릴리스 차단 후 재작업. 점수 = 가중 합(100점).

| 영역 | 항목 | 배점 |
|------|------|------|
| RAG 품질 | groundedness, citation 정확도, answer relevance (골든셋 평가) | 30 |
| 회의 품질 | WER(전사), 요약 충실도(rouge/사람검수 표본) | 20 |
| 성능 | 첫 토큰 지연, 인제스천 처리량, 메모리 상한 준수 | 15 |
| 보안 | pip-audit 무결점, 네트워크 격리 테스트 통과, 인증/CORS 테스트 | 20 |
| 안정성 | 유닛/통합 테스트 통과율, 크래시프리 세션 | 15 |

**게이트**: 총점 ≥ 85 **그리고** 보안 영역 감점 0 이어야 릴리스. 미달 시 실패 항목이 다음 스프린트 백로그로 자동 복귀(= 사용자가 말한 "처음으로 돌아가 재작업").
