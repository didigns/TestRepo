플러그인 제작 가이드

AISummary는 100% 로컬 · 제로 노출을 지키면서 확장 가능한 플러그인 플랫폼입니다. 이 문서는 플러그인을 만드는 세 가지 방법과 호스트 API를 설명합니다.

1. 개요와 철학

이 앱의 모든 확장 기능은 플러그인입니다. 소설 메이커, 요약 도우미 같은 기능도 전부 같은 플러그인 시스템 위에 얹혀 있습니다. 플러그인을 설계할 때 관통하는 원칙은 하나입니다.

제로 노출(zero-exposure)은 구조로 보장됩니다. 플러그인에게는 네트워크로 나가는 통로 자체를 주지 않습니다. 선언형은 코드를 실행하지 않고, WASM에는 네트워크 import를 주입하지 않습니다. 그래서 커뮤니티 플러그인이라도 데이터 유출은 "정책"이 아니라 "불가능"입니다.

플러그인은 필요한 복잡도에 따라 세 티어 중 하나로 만듭니다. 대부분은 T0+T1로 충분하고, 진짜 코드가 필요한 경우에만 T2(WASM)를 씁니다.

T0 선언형

코드 실행 0
  • 페르소나 / 시스템 프롬프트
  • 선언형 UI 컴포넌트 트리
  • 지식 팩(격리 벡터)

T1 flow-DSL

데이터로 기술한 로직
  • 장면·선택·분기 흐름
  • 안전 수식(expr) 스크립팅
  • 스탯 + 상태창

T2 WASM

매개 host API
  • 임의 코드(AS/Rust/TinyGo)
  • 커스텀 파싱·계산
  • 네트워크 import 없음

2. 빠른 시작

가장 단순한 플러그인은 페르소나만 지정하는 T0 플러그인입니다. 플러그인 폴더를 만들고 plugin.json 하나만 넣으면 됩니다.

폴더 위치

  • 빌트인(1st-party): backend/aisummary/plugins/builtin/<id>/
  • 사용자 설치: ~/.aisummary/plugins/<id>/
// plugins/builtin/summary-helper/plugin.json — 최소 플러그인
{
  "manifestVersion": 1,
  "id": "summary-helper",
  "name": "요약 도우미",
  "version": "1.0.0",
  "permissions": { "folders": ["*"], "network": false,
    "capabilities": ["model:generate"] },
  "contributes": {
    "mode": {
      "label": "요약 도우미",
      "icon": "📝",
      "persona": "너는 문서를 간결하게 요약하는 도우미야. 핵심만 3줄로."
    }
  }
}

빌트인 플러그인은 기본으로 켜져 있고, 사용자 플러그인은 설정 → 플러그인에서 켜야 합니다. 켜면 좌측 내비게이션에 모드 버튼이 생깁니다.

3. plugin.json 매니페스트

매니페스트는 순수 데이터입니다. 어떤 코드도 실행되지 않으며, 검증에 실패한 매니페스트는 목록에만 표시되고 켤 수 없습니다.

필드필수설명
manifestVersion✓현재 1
id✓고유 식별자(폴더명과 일치 권장)
name · version✓표시 이름 / 시맨틱 버전
author · description메타데이터
entryT2WASM 모듈 파일명(예: "plugin.wasm"). 있으면 T2로 로드
permissions.folders허가 폴더 스코프. []=문서 접근 없음, ["*"]=전체
permissions.network항상 false. 제공하지 않는 불변값
permissions.capabilities사용하는 능력 목록(§Host API)
contributes.mode이 플러그인이 기여하는 모드 화면(아래)

contributes.mode 필드

필드티어설명
label · icon공통내비게이션 표시
personaT0/T1생성 시 주입할 시스템 프롬프트
viewT0메인 화면에 그릴 선언형 컴포넌트 트리
sidebarT0사이드바에 그릴 컴포넌트 트리
flowT1flow-DSL 흐름({start, steps})
statsT1스탯 정의(초기화 + 상태창 자동 생성)
statusT1상태창 사양(생략 시 stats에서 자동 구성)
T2(WASM) 플러그인은 보통 mode에 label/icon만 두고, 실제 화면은 WASM이 런타임에 그립니다. entry가 있으면 호스트는 flow/view 대신 WASM 런타임을 띄웁니다.

T0 · 선언형 코드 0

페르소나만으로 부족하면 view에 컴포넌트 트리를 선언해 커스텀 화면을 만들 수 있습니다. 버튼의 action으로 생성을 트리거합니다.

{
  "contributes": { "mode": {
    "label": "브리프 빌더", "icon": "🗂️",
    "view": [
      { "type": "Text", "props": { "text": "주제를 입력하세요" } },
      { "type": "Input", "id": "topic", "props": { "placeholder": "예: 2분기 실적" } },
      { "type": "Button", "props": { "label": "생성", "variant": "primary" },
        "action": { "type": "generate", "prompt": "{{topic}} 브리프를 써줘", "output": "out" } },
      { "type": "Markdown", "id": "out", "props": { "text": "" } }
    ]
  } }
}

{{var}}는 같은 화면의 id를 가진 입력값으로 치환됩니다. 사용 가능한 컴포넌트는 §컴포넌트 레퍼런스를 보세요.

위 view가 이렇게 렌더링됩니다
주제를 입력하세요
2분기 실적 브리프
매출은 전분기 대비 12% 성장했고, 신규 고객 유입이 핵심 동인이었다. 비용은 안정적으로 관리되어 영업이익률이 개선되었다.

T1 · flow-DSL 데이터 로직

flow-DSL은 다단계 로직(장면 → 선택 → 생성 → 분기)을 데이터로 기술합니다. 호스트가 프론트엔드에서 해석하므로 플러그인 코드는 실행되지 않습니다. 구조는 { start, steps:{ <id>: <step> } } 이며 실행 중 state(변수)와 {{var}} 템플릿을 씁니다.

스텝 타입

스텝필드동작
texttext, next고정 지문(마크다운). LLM 호출 없음
setvars{}, next변수 설정. 값은 "{{템플릿}}" 또는 {expr:"..."}
generateprompt, grounded, into, nextLLM 호출. grounded:true=검색+인용, false=자유 생성
choiceprompt?, options[]선택지 버튼 → set 적용 후 goto
inputlabel?, into, next유저 텍스트 입력을 변수에
ifcond{expr}, then, else수식 조건 분기
goto · endto / —점프 / 종료

안전 수식(expr) — 스크립팅

호스트가 eval 없이 자체 파서로 해석합니다. 숫자·문자열·변수, 산술 + - * / %, 비교 < > <= >= == !=, 논리 && ||, 괄호만 지원합니다. 정해진 문법만 인식하므로 임의 코드 실행이 구조적으로 불가능합니다.

스탯 + 상태창

mode.stats를 선언하면 (1) 플로우 시작 시 state[key]=initial로 초기화되고, (2) show:true인 스탯으로 사이드바 상태창이 자동 생성됩니다.

{
  "mode": {
    "persona": "너는 인터랙티브 소설의 진행자야. 2인칭, 짧게.",
    "stats": [
      { "key": "hp", "label": "체력", "initial": 100, "max": 100, "bar": true, "show": true }
    ],
    "flow": {
      "start": "intro",
      "steps": {
        "intro":  { "type": "generate", "grounded": false,
                    "prompt": "폭풍우 치는 밤, 저택 앞 도입부를 3문장.", "into": "scene", "next": "c1" },
        "c1":     { "type": "choice", "prompt": "무엇을 할까?", "options": [
                    { "label": "문을 연다 (체력 -20)",
                      "set": { "hp": { "expr": "hp-20" } }, "goto": "route" },
                    { "label": "돌아선다", "goto": "route" } ] },
        "route":  { "type": "if", "cond": { "expr": "hp<=40" },
                    "then": "bad", "else": "good" },
        "bad":    { "type": "text", "text": "쓰러지고 만다…", "next": "done" },
        "good":   { "type": "text", "text": "살아남았다.", "next": "done" },
        "done":   { "type": "end" }
      }
    }
  }
}
위 flow를 플레이하면 — 지문·선택지 + 사이드바 상태창
비바람이 몰아치는 밤, 낡은 저택의 문이 삐걱인다. 안에서 희미한 불빛이 새어 나온다.
무엇을 할까?
주인공 상태
체력80 / 100
정신력35 / 100

막대는 잔량에 따라 색이 바뀝니다 — ≤25% 적색 · ≤50% 황색(정신력) · 그 외 강조색(체력). 선택지의 set:{hp:{expr:"hp-20"}}가 상태창에 즉시 반영됩니다.

T2 · WASM 임의 코드

진짜 코드(커스텀 파싱, 복잡한 상태, 저작 도구)가 필요하면 .wasm 모듈을 싣습니다. 호스트가 인스턴스화할 때 주입하는 import는 매개 함수뿐이라, 계산·저장·렌더는 해도 밖으로 내보낼 통로가 없습니다. 매니페스트에 entry와 code:wasm 능력을 선언합니다.

{
  "id": "novel-maker", "name": "소설 메이커", "version": "1.0.0",
  "entry": "plugin.wasm",
  "permissions": { "folders": [], "network": false,
    "capabilities": ["code:wasm", "model:generate", "ui:render", "storage:local"] },
  "contributes": { "mode": { "label": "소설 메이커", "icon": "📖" } }
}

ABI (호스트 ↔ WASM)

문자열은 UTF-8로 선형 메모리에 주고받습니다. WASM은 alloc(size) / dealloc(ptr,size)와 memory를 export 합니다.

WASM이 export (호스트가 호출)

함수의미
on_init(ptr,len)저장소 스냅샷 {storage:{key:value}} 전달(시작 시)
on_event(hPtr,hLen,pPtr,pLen)UI 이벤트: 핸들러 문자열 + 값
on_generate_done(reqId,ptr,len)생성 결과 텍스트 전달

WASM이 import (능력의 전부 — 이게 샌드박스)

함수의미
host_ui_render(ptr,len)컴포넌트 트리 {surface,body[]}를 그려달라
host_generate(reqId,ptr,len){prompt,persona}로 생성. 결과는 on_generate_done으로
host_storage_save/delete(ptr,len)플러그인 격리 저장소 {key,value}
host_export(ptr,len)완성 매니페스트를 새 플러그인으로 설치
host_preview(ptr,len){persona,stats,flow}를 호스트 런타임이 플레이
host_toast/log(ptr,len)알림 / 디버그 로그
여기 host_fetch류는 없습니다. 네트워크 import가 존재하지 않으니 WASM이 아무리 임의 코드를 실행해도 데이터를 밖으로 보낼 수 없습니다. 호스트는 모든 WASM 진입 호출을 try/catch로 감싸 abort 시에도 앱이 죽지 않습니다.

UI 노드 프로토콜

WASM이 host_ui_render로 보내는 body[]의 노드 형식입니다. 텍스트 입력은 onchange(blur)로 값을 되돌려주므로 타이핑 중 리렌더로 포커스를 잃지 않습니다.

{ "surface": "main"|"sidebar", "body": [
  { "t":"Text", "text":"...", "muted":true },
  { "t":"MD",   "text":"**마크다운**" },
  { "t":"In",   "val":"...", "ph":"placeholder", "ev":"field:s1:text", "num":false },
  { "t":"TA",   "val":"...", "ev":"..." },
  { "t":"Sel",  "val":"a", "opts":[{"v":"a","l":"A"}], "ev":"..." },
  { "t":"Chk",  "checked":true, "label":"표시", "ev":"..." },
  { "t":"Btn",  "label":"저장", "ev":"save", "variant":"primary" },
  { "t":"Row"|"Col", "c":[ /* 자식 노드 */ ] },
  { "t":"Card"|"Item", "cls":"nv-scene", "ev":"open:s1", "c":[ ... ] },
  { "t":"Hr" }
] }

이벤트는 on_event(handler, value)로 되돌아옵니다. ev 문자열에 대상 정보를 인코딩하세요(예: "field:s1:text").

WASM은 상태가 바뀔 때마다 이 트리를 다시 내보내고, 호스트가 우리 컴포넌트로만 다시 그립니다. 원시 HTML은 개입하지 않습니다.

빌드 (AssemblyScript 예시)

# 툴체인
npm i -g assemblyscript      # asc 컴파일러
npm i assemblyscript-json     # AS용 JSON

# 컴파일
asc src/main.ts -o plugin.wasm --optimize --exportRuntime --lib ./node_modules

Rust(wasm32-unknown-unknown), TinyGo 등 WASM으로 컴파일되는 언어면 무엇이든 됩니다. 위 import/export 규약만 지키면 됩니다.

컴포넌트 레퍼런스

T0 view와 T2 UI는 모두 호스트가 우리 컴포넌트로만 렌더합니다. 원시 HTML/JS는 허용되지 않습니다.

Host API & 능력

플러그인이 선언하는 능력은 대응하는 호스트 기능에만 연결됩니다. 허가되지 않은 기능은 애초에 링크되지 않습니다.

능력(capability)호스트 기능
model:generatePOST /host/generate/stream — 무근거/근거 생성, 페르소나 인라인, 추론 큐 경유
storage:local/host/storage/{pid}/{list,load,save,delete} — 플러그인별 격리 폴더(경로 핸들 미제공)
ui:render메인/사이드바 표면 렌더
documents:read허가 폴더 스코프 검색
knowledgePack자기 지식 팩 검색(격리 네임스페이스)
code:wasmT2 WASM 실행
network제공하지 않음(불변)

플러그인이 만든 매니페스트를 새 플러그인으로 설치할 때는 POST /host/plugins/export를 쓰며, 기록 시 network:false가 강제됩니다. 저장소는 ~/.aisummary/plugin-data/{pid}/에 격리됩니다.

권한 & 신뢰 등급

  • builtin (1st-party, 앱 동봉) > verified (서명·심사) > community (무서명)
  • community라도 네트워크가 애초에 없으므로 유출 위험은 구조적으로 0. 대신 리소스 남용·품질은 리뷰/제한으로 관리
  • enable 시 권한 시트 표시 → 허가 저장. 업데이트가 권한을 더 요구하면 권한 diff 재동의
  • 빌트인은 기본 켜짐, 사용자 플러그인은 기본 꺼짐

4. 배포

  1. 폴더 구성 — <id>/plugin.json (+ T2면 plugin.wasm, 소스는 src/)
  2. 배치 — 사용자 설치는 ~/.aisummary/plugins/<id>/에 폴더째 넣기
  3. 활성화 — 설정 → 플러그인에서 켜기(빌트인은 자동)
  4. 앱에서 생성 — 소설 메이커처럼 앱 안에서 host_export로 완성물을 플러그인으로 내보내면 즉시 설치·활성화

5. 체크리스트

  • ✅ manifestVersion/id/name/version 있음
  • ✅ permissions.network는 false
  • ✅ 필요한 능력만 capabilities에 선언(최소 권한)
  • ✅ T0/T1이면 코드 없이 데이터만으로 표현되는가
  • ✅ T2면 import는 매개 host 함수뿐, 네트워크 import 없음
